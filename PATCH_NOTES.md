# Patch Notes

Newest day first. One line per finished item.

## 2026-10-28
- Phase 4b slice 5: one combat path. One `combat.Attack` and one combat round serve every actor (accounts act first, as before); combat text goes through messaging, one message per swing. Rulings: a hidden attacker reads "Someone" in every line others see (waits included, which used to be hidden); anyone fighting a fleer may block the flee (players never could, an upstream bug), and a blocked fleer goes back to its fight; every swing earns kill credit, hit or miss, for the attacker's account or a pet's owner (PvP misses now count). NPCs flee and leave the room. Fixed drift: an NPC's offhand can break under a player's hit; broken items land in the defender's room; aggro changes always reach GMCP; a player downed in combat records the killer (elite deaths and killer IDs now work; the record clears on recovery). Combat lines: mob names lose adjectives such as "(charmed)" and doubled colour tags; a possessive `'s` sits outside the name colour; in a dark room names read "someone". A golden combat test (seedable RNG for tests) pins outcomes; smoke fights a rat, and a second bot must see only the observer lines
- Phase 4b slice 4: one command set and one input path. Players and NPCs run the same commands (`usercommands.Command` takes the actor; account-only parts ask for an account) through one router; `internal/mobcommands` deleted. Rulings: action points regenerate and are charged for every actor (link-dead players included); NPCs use the player wording (an NPC shout is upper case and reaches the next rooms); an NPC's unknown command is logged, not shown; nobody walks or quits out of a fight, players included: a player an NPC is attacking must flee (NPCs therefore no longer chase a player who walks off). One `MoveToRoom` moves any body (NPCs now get room mutator buffs). `wander`, `pathto` and `rest` are behaviour actions (`internal/behaviour`); `suicide` branches to NPC death until slice 5. Dropped (nothing issued them): `sayto`, `saytoonly`, `replyto`, `despawn`, `equip all/random`, `go <roomId>`. Fixed upstream bugs found in the fold: NPC `put` minted gold and ignored locks, NPC `remove` ignored curses, user `give` crashed on a missing target, `EventFlag.Add` cleared the flag, the follow module's "stopped following you" named the wrong person. Guards: one command set, no `AddMobCommand`, no dropped verbs queued as commands. Smoke: an NPC speaks through the shared path
- Phase 4b slice 3: messaging core. `internal/perception` is the vocabulary (message kinds, senses, ranges room/nearby/zone/world, audiences, roles); `internal/messaging.Send` finds who a message reaches, checks each receiver with the replaceable `CanPerceive` (sight needs light or nightvision, a faint sound needs superhearing), picks the role and text, resolves `{actor}`, `{target}` and `{direction}` per receiver ("Someone" when unseen), and hands it to the controller: text to a player's output queue, a structured perception to an NPC behaviour hook. Nothing calls it in play yet (slices 5 and 7). Guard: direct connection writes only in messaging, with today's 15 writers on an allowlist that may only shrink (GMCP excepted)
- Phase 4b slice 2c: item IDs. Every item's ID is an `ids.ID`, saved as `id` and kept for good (upstream's UUID was never saved, so every load made new ones; `internal/uuid` deleted). Items saved before this get their ID at first load. Template files (rooms, mobs) never hold item IDs, and a new NPC gets its own items: before, every NPC of one template shared the template's item IDs. Fixed upstream bugs on the way: admin Save User merged each posted item, shop entry and equipment slot into whatever sat at that position (moving uses, adjectives and IDs between items, and changing the live record even when the save failed); room template saves given the live room appended its floor items to themselves; new mob template files written by `mob create` carried item IDs. The `!N` and `!N:<uuid>` item forms are gone (clients send the ID token). Unused `accounts.Storage` and `Mob.Save` deleted. Guards: IDs made only at creation sites, template items instantiated only on the NPC-from-template path, no `!%d`

## 2026-10-27
- Phase 4b slice 2b: NPCs are saved world state (decisions 12-17). An NPC survives copyover, restart, room unload, boredom and charm expiry with its ID, health, items, gold, buffs, aggro and charm; it rests in its room's sidecar (`rooms.instances/<zone>/<id>.npcs.yaml`) and comes back when its room next loads. Spawn slots keep their NPC until it dies or an admin despawns it (endings ledger `rooms.instances/npcs.endings.yaml`), which also fixes upstream's duplicate of a wandering NPC when its home room reloaded. Crash-safe write order, one copy of an NPC on disk. Companions save with their player. Spawn-slot permanent buffs removed (never worked; a variant is its own template)
- Phase 4b slice 2: one ID scheme, `0x<cell>:0x<random>` (`internal/ids`, decisions 10-11). Every body's ID lives on its `Character`; a player's is made at character creation and saved (startup migration for existing characters; `cmd/newid` for hand-made content); a mob instance's is its identity (instance counter gone). Rooms, aggro, charm, killer, events, actors and GMCP hold it; `#N`/`@N` are gone (clients send ID tokens, people type names). Fixed upstream bugs: follow treated a mob's template ID as its instance ID; player tracking read NPC visitors as user IDs; `#1` would have matched the first mob by position. Guards: no `MobInstanceId`, IDs made only at creation sites, no `#N`/`@N`

- Login splash rewritten for GeOMUD (gridded globe and GeOMUD logo, one-line pitch, our repo link); `Server.MudName` is `GeOMUD` (web pages, GMCP `Game.Info`, Mudlet, server log)
- Phase 4b design spec (`2026-10-27-phase-4b-npcs-are-players-design.md`): one actor model, unified messaging, seven slices with one plan each
- Phase 4b slice 1: every player and mob is an actor (`internal/actors`: one `ActorId` space, swappable controller, registry wired to account and mob lifecycle hooks); `users` renamed `accounts` (`UserRecord` is `Account`) with connection state in `Session`; account hooks fire in online-map order; guard tests in `internal/guards`; smoke `-transcript` with the pre-4b baseline and a live copyover step (Linux CI); copyover no longer drops a link-dead player's flag (upstream bug)
